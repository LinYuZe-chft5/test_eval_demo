# Codex_02 PRD：H5线上学科诊断验证应用

**版本**：V1.0（MVP验证版）  **状态**：可进入开发
**核心声明**：本应用的唯一目标是**验证**——验证3天诊断设计、报告价值与付费意愿。所有功能取舍服从验证目标，非验证必需的功能一律裁剪。

---

## 1. 项目核心目标（一句话）

种子用户通过访问码在手机H5上分3天完成数学诊断测试，系统自动判分与行为采集，规则引擎组装诊断报告，分析师复核发布，家长查看报告并填写反馈问卷——用真实数据回答四个问题：**完测率够不够？报告值不值？家长愿不愿付费？会不会复购？**

## 2. 用户角色

| 角色 | 进入方式 | 核心动作 |
|---|---|---|
| 学生（初中生） | 访问码链接 | 分3天作答、标记"我不会/蒙的" |
| 家长 | 报告token链接（学生完成后由运营发送） | 查看报告、填写反馈问卷 |
| 分析师 | 后台登录 | 复核编辑报告、发布、查看数据 |
| 运营（你） | 后台登录 | 生成访问码、导入题库、导出数据 |

MVP中学生与家长账号体系合并：访问码绑定一个学生档案，报告token与家长一一对应，不建独立家长账号。

## 3. 核心业务流程

```text
运营导入题库（JSON）→ 生成访问码（N个）→ 分发给种子家庭
  ↓
学生Day1：入口页（须知+建档）→ 热身题2道 → 正式作答 → 完成页
  ↓（次日解锁，7天窗口期内有效）
学生Day2：同上  → 学生Day3：同上
  ↓ Day3提交后自动触发
规则引擎组装报告草稿 → 分析师后台复核（可编辑）→ 发布
  ↓
运营将报告链接发给家长 → 家长查看报告 → 填写反馈问卷
  ↓
运营导出验证指标数据（完测率/NPS/付费意愿/复测意向）
```

**状态机强制规则**：
- Day2/Day3未解锁时，禁止访问作答页（显示"明天再来"）；
- 当日已提交（submitted）后，禁止再次作答；
- 报告未发布（status≠published）时，报告token链接显示"报告生成中"。

## 4. 功能需求清单（P0/P1）

### 4.1 访问与建档模块（P0）

| 编号 | 需求 | 说明 |
|---|---|---|
| F1.1 | 访问码校验 | 8位随机码；无效/过期/已用完给出明确提示 |
| F1.2 | 学生建档 | 昵称（非真名）+年级+学校（选填）；一码只能建档一次 |
| F1.3 | 须知页 | 固定文案：3天流程说明、数据告知（"本测试将记录答题时长等过程数据，仅用于生成诊断报告"）、安静环境建议、"没有对错排名"的减压提示 |
| F1.4 | 后台生成访问码 | 批量生成N个码，支持导出清单（码+状态+绑定学生） |

### 4.2 作答引擎（P0）

| 编号 | 需求 | 说明 |
|---|---|---|
| F2.1 | 一屏一题 | 移动端优先；字体≥16px；KaTeX渲染公式；图形题图片+文字双标注；禁止左右滑动 |
| F2.2 | 题型支持 | ①单选（4选项，可修改，记录切换路径）②填空（数字键盘+符号快捷栏π/√/°/分数）③分步解答（2-3个递进输入框，逐框提交） |
| F2.3 | 回翻只读 | 允许查看已提交题目，禁止修改；记录回翻次数 |
| F2.4 | "我不会/蒙的"标记 | 每题一个标记按钮，仅记录不影响判分 |
| F2.5 | 断点续答 | 中断后重新进入恢复至最后作答题；事件缓冲不丢失 |
| F2.6 | 当日限时 | 每日常规时长：Day1=30分钟/Day2=35分钟/Day3=40分钟（规则常量），超时强制交卷；剩余5分钟提示一次 |
| F2.7 | 热身题 | 每日开头2道超基础题，不计分；作答数据进入低信度校验 |
| F2.8 | 三天流程控制 | Day2/Day3按规则解锁（次日0点或运营手动提前）；7天窗口期 |
| F2.9 | 中性完成页 | 仅显示进度（"已完成2/3天"）与参与质量话术（"答题专注度良好"），**严禁显示任何分数、对错、模块得分** |

### 4.3 判分与行为采集（P0）

| 编号 | 需求 | 说明 |
|---|---|---|
| F3.1 | 客观题自动判分 | 选择题精确匹配；填空题按题目answer_spec字段规范化判分（规则见Codex_04第2章） |
| F3.2 | 分步解答判分 | 每个分步输入框独立判分独立记录 |
| F3.3 | 行为埋点 | 采集字段见DDL的answer_records与answer_events：进入/首次点击/选项切换/修改/删除重写/提交时间戳/回翻/标记；批量上报（每10秒或切题） |
| F3.4 | 低置信度检测 | 秒选答对（耗时<预期时长×0.4）→触发二次探测（规则见Codex_04第3章） |
| F3.5 | 低信度答卷 | 三取二联合判定，写入session标记 |

### 4.4 报告引擎与后台（P0）

| 编号 | 需求 | 说明 |
|---|---|---|
| F4.1 | 报告草稿自动组装 | Day3提交后≤5秒生成draft；数据契约见Codex_04第6章 |
| F4.2 | 分析师复核工作台 | 报告列表（待复核置顶）+详情编辑：可修改个性化段落文本、调整首要/次要错因（下拉EC编码）、编辑建议文本；每处修改留痕（analyst_edits） |
| F4.3 | 发布与链接 | 发布后生成家长token链接，一键复制 |
| F4.4 | 题库导入 | JSON文件上传导入（格式见Codex_05），导入前Schema校验+查重（考点+题干hash），错误行级报错 |
| F4.5 | 数据导出 | 一键导出CSV：作答明细、题目维度汇总（实测P值/区分度粗算）、反馈问卷结果 |

### 4.5 报告展示（家长端，P0）

七段式结构（与产品总规范5.6一致）：

| 段落 | 内容 | MVP实现 |
|---|---|---|
| 一、总体画像 | 总分+适应性三级评定（达标/基本达标/待加强） | 标准参照话术；百分位字段留空（降级文案："常模数据积累中，本期不展示同龄比较"） |
| 二、知识模块雷达图 | 4-6个模块掌握度 | Recharts雷达图，红/黄/绿三色 |
| 三、核心素养雷达图 | 主导素养维度表现 | 同上 |
| 四、错因归因分析 | 首要错因+次要错因（EC编码+人话名称+占比）+对应方法卡内容 | 方法卡内容从method_cards表取预制文本 |
| 五、个性化诊断段落 | 200-300字叙述 | **分析师后台手填**（AI二期），未填则隐藏本段 |
| 六、4周提分计划 | 按周列出重点考点+方法 | pathEngine自动生成 |
| 七、本周行动清单 | 3个可勾选行动+第4项"预约复测" | 复测意向点击即记录 |

### 4.6 反馈问卷模块（P0，验证核心）

报告页底部固定入口，字段：

| 字段 | 类型 | 验证目的 |
|---|---|---|
| NPS：您愿意把这份诊断推荐给其他家长吗（0-10） | 评分 | 报告价值 |
| 报告最有价值的部分 | 多选（雷达图/错因分析/4周计划/行动清单/真人讲解建议） | 产品迭代方向 |
| 若为完整服务（含30分钟真人讲解），您愿意支付的价格 | 单选（<68 / 68-99 / 99-159 / 159-199 / >199元） | 定价验证 |
| 您是否愿意8周后复测 | 单选（愿意/看情况/不愿意） | 复购钩子 |
| 开放反馈 | 文本（选填） | 定性洞察 |

### 4.7 运营看板（P1）

后台首页四张卡片：访问码使用率、Day1→Day3完测漏斗、报告待复核数、反馈问卷回收数与NPS均值。MVP不做复杂图表。

## 5. 前端交互强制规范（测量学红线）

1. **过程零反馈**：作答全程不出现分数、对错、正确率、模块得分、排名；唯一允许的是进度信息；
2. **回翻只读**：可回看，不可修改；
3. **中性话术**：完成页只鼓励坚持（"已完成2/3天"），不评价能力；
4. **题目呈现**：KaTeX渲染；图形题图片宽度100%、关键条件图下文字复述；
5. **防误触**：提交按钮二次确认仅限当日最后一题（"提交后今日不可再修改"）；
6. **告知文案**：入口须知页固定展示过程数据采集告知。

## 6. 后台页面规格

| 页面 | 内容 |
|---|---|
| /admin | 看板四卡（4.7） |
| /admin/codes | 访问码生成/列表/状态 |
| /admin/questions | 题库列表（只读+检索）、JSON导入入口、导入结果报告 |
| /admin/reports | 报告列表：学生/天数完成状态/可信度标记/报告状态（draft/published）/操作 |
| /admin/reports/[id] | 报告复核编辑页：左=系统组装数据（只读），右=可编辑区（叙述段、错因下拉、建议文本），底部=发布按钮+修改留痕 |
| /admin/export | CSV导出（作答明细/题目汇总/反馈） |

单题复核操作目标≤3次点击（确认/修改/发布）。

## 7. 非功能性需求

| 指标 | 要求 |
|---|---|
| 设备 | 手机H5优先（iOS Safari/微信内置浏览器/Android Chrome兼容）；后台桌面端 |
| 性能 | 首屏≤3秒(4G)、单题提交≤1秒、报告组装≤5秒 |
| 并发 | 100同时在线 |
| 可靠性 | 埋点事件本地缓冲，网络恢复后重传不丢失 |
| 数据 | 每日自动备份（Supabase默认）；导出CSV可随时全量取回 |

## 8. 验收标准（硬性红线，逐条过）

1. **建库验收**：DDL全部表创建成功；种子题库JSON（≥10题含3种题型）导入成功且Schema校验拦截1条故意错误数据；
2. **访问码验收**：错误码/过期码/重复使用均被拦截并提示；
3. **流程验收**：模拟学生完成Day1后，Day2入口显示"明天再来"；手动改时间后解锁；
4. **作答验收**：一屏一题；回翻可查看但修改被拦截；断网重连后作答进度与已缓冲事件无丢失；
5. **限时验收**：模拟超时，系统自动交卷且已作答数据完整；
6. **反馈红线验收**：作答全程页面源码中不出现任何分数/对错字样（抽查）；
7. **判分验收**：填空题按answer_spec判分——"0.5"与"1/2"按规范处理（含容差案例），错误形式一律判错；
8. **探测验收**：模拟1秒秒选答对→系统自动追加同考点平行题→平行题答错后原题标记"疑似蒙对"且不计入掌握度；
9. **低信度验收**：模拟三取二条件→session生成低信度标记→报告草稿含降级文案；
10. **报告验收**：用种子数据生成报告草稿，七段数据契约字段齐全（允许叙述段为空）；
11. **复核验收**：分析师编辑叙述段+修改错因→留痕→发布→家长链接可见；编辑前链接显示"报告生成中"；
12. **导入验收**：导入含重复考点的JSON，系统报告冲突行号；
13. **问卷验收**：报告页提交问卷，后台可见NPS与付费意愿分布；
14. **导出验收**：导出CSV包含answer_records全字段，可直接用于CTT分析。
