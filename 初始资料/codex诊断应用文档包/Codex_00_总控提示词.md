# Codex 总控提示词（先读我）

> 本文件是使用 AI 编程助手（Codex/Cursor/Claude Code 等）开发本项目的**总控指令**。
> 开始任何编码前，请将本文件全文提供给编程助手，并按"构建顺序"逐里程碑提交需求。

---

## 一、给编程助手的角色指令（直接粘贴）

```text
你是一名资深全栈工程师，负责开发一个"H5线上学科诊断验证应用"（MVP）。
这是一个教育测量产品，不是普通问卷系统。本项目的每一条规则都来自一份
产品总规范，规则的测量学含义你不理解时不要擅自简化——先提问，再实现。

【必读文档】按以下顺序阅读项目文档包，全部读完再写第一行代码：
1. Codex_01_架构设计.md      —— 技术栈、模块划分、数据流
2. Codex_02_PRD.md           —— 用户角色、业务流程、页面规格、验收红线
3. Codex_03_数据库DDL.sql    —— 数据库结构（唯一事实来源，禁止自行改表结构）
4. Codex_04_规则引擎规格.md  —— 判分、行为分析、二次探测、报告组装的全部规则
5. Codex_05_题库与内容数据格式.md —— 题目JSON Schema与导入格式

【铁律】
1. 遇到逻辑不清时，优先参考文档中的"规则"而非你的"学术直觉"；
   文档之间冲突时，以 Codex_04_规则引擎规格.md 为准，并向我报告冲突点。
2. 禁止引入文档未指定的第三方服务（如AI大模型API、OCR、短信服务）。
3. 所有标注"待校准"的阈值参数（如0.4、20%、3次）必须抽取为配置文件
   config/rules.ts 中的命名常量，禁止硬编码散落在代码里。
4. 每个规则函数必须配套单元测试，测试用例来自规则文档中的示例。
5. 数据库结构以DDL文件为唯一事实来源，ORM模型由DDL生成，不得反向修改DDL。
6. 这是MVP验证应用：优先保证规则正确性和数据完整性，其次才是UI美观。
```

## 二、项目一句话定义

面向种子用户的**3天制线上数学诊断验证应用**：学生通过手机H5分3天完成诊断测试，系统自动判分并采集作答行为数据，规则引擎自动组装诊断报告草稿，分析师后台复核后发布，家长查看报告并填写反馈问卷（验证付费意愿）。

## 三、技术栈（已冻结，禁止更换）

| 层 | 选型 | 理由 |
|---|---|---|
| 全栈框架 | Next.js 14+（App Router）+ TypeScript | 前后端一体，Codex生成效率高 |
| 样式 | Tailwind CSS（移动端优先） | 快速开发H5 |
| 数据库 | PostgreSQL（Supabase免费层） | JSONB支持行为事件存储 |
| ORM | Prisma（模型由DDL生成） | 类型安全 |
| 数学渲染 | KaTeX（react-katex或@matejmazur/react-katex） | 轻量、移动端稳定 |
| 部署 | Vercel + Supabase | 零成本起步 |
| 图表 | Recharts（雷达图） | 报告页可视化 |

**明确不使用**：Redis（MVP不需要）、WebSocket（无实时需求）、AI大模型API（二期）、对象存储（MVP不做拍照上传）。

## 四、构建顺序（6个里程碑，逐个完成验收后再进入下一个）

| 里程碑 | 内容 | 验收依据 |
|---|---|---|
| M1 数据基座 | DDL建表、Prisma模型、种子数据导入脚本、访问码生成脚本 | PRD第8章验收1-2 |
| M2 学生作答引擎 | 访问码进入、一屏一题、回翻只读、分步解答、断点续答、三天流程控制 | PRD第8章验收3-6 |
| M3 判分与行为引擎 | 客观题判分、答案规范化、埋点批量上报、低置信度检测、二次探测 | PRD第8章验收7-9 |
| M4 报告组装引擎 | 掌握度判定、错因分布、路径定序、报告草稿生成 | 规则文档第6章全部用例 |
| M5 分析师后台 | 报告复核编辑发布、题库导入、数据导出、反馈看板 | PRD第8章验收10-12 |
| M6 家长端与反馈闭环 | 报告展示页（雷达图）、反馈问卷、复测意向收集 | PRD第8章验收13-14 |

## 六、范围裁剪红线（MVP不做，写入代码注释标记TODO-V2）

- 不做CAT自适应选题（按蓝皮书固定题序）
- 不做IRT参数计算（仅用题库预置的预估难度字段）
- 不做拍照上传与OCR（解答题全部"分步客观化"）
- 不做AI大模型报告段落（报告"个性化段落"字段预留，由分析师后台手填）
- 不做微信支付（本应用是验证工具，支付在线下进行）
- 不做短信验证（访问码机制替代注册登录）
- 不做多学科（仅数学，但所有表结构已预留subject字段）

## 七、验证目标提醒（写给开发者和运营者）

本应用的KPI不是日活，而是：
1. **完测率**（Day1开始→Day3完成 ≥70%）——验证3天设计；
2. **报告满意度**（反馈问卷NPS ≥8/10）——验证产品价值；
3. **复测意向率**（≥30%）——验证复购钩子；
4. **付费意愿**（问卷直接询问可接受价格区间）——验证定价。

因此反馈问卷模块与数据导出模块与答题模块同等重要，不得降级。
